# 自适应层级分栏与移动页面转场

状态为在功能 worktree 实施并验收，更新于 2026-11-24。适用于 workbench-kit，首个消费方为 llm-bot 的多层设置。实现采用受控页面链、单栏双页转场和设置结构操作。本文保留设计背景与回归验收场景。

当前 llm-bot 接入将分类固定在桌面侧栏，手机映射到独立一级页。本文的分栏计算只作用于详情区域。手机的根区进退由移动外壳呈现，同区域深层导航由详情容器呈现。两个容器复用同一双页过渡逻辑。

## 1. 用户看到什么

用户打开深层设置时，应能在空间允许的范围内看到当前页是从哪里进入的，也能在可见父栏直接选择另一个条目。路径再深，当前页始终占最右栏。手机上一次操作一页，子页从右边盖住父页，返回时揭开的就是刚才那一层。

以下用「设置 → 供应商 → 甲 → 模型列表」说明。方括号中的每项是一栏，左侧为上层。

| 操作 | 操作后的页面 | 可观察的结果 |
| --- | --- | --- |
| 三栏宽度直接打开模型列表 | [供应商] [甲] [模型列表] | 供应商栏选中甲，甲栏选中模型列表，面包屑仍能返回设置 |
| 此时在供应商栏点乙 | [设置] [供应商] [乙] | 甲及其后代离场，设置根栏自然补回，无须先逐层返回 |
| 在模型列表的位置将容器缩至两栏 | [甲] [模型列表] | 模型列表中的输入和滚动位置保留，历史记录不变 |
| 单栏宽度从模型列表返回 | [甲] | 模型列表向右退出，露出已恢复滚动位置的甲页 |
| 从搜索结果跳到甲的一个标量字段 | 当前页为包含该字段的页面 | 字段获得焦点，字段名不额外占栏 |

## 3. 页面链与渲染契约

建议在 `vue-workbench` 新增可选组件 `WorkbenchPageColumns`，经 `@workbench-kit/vue` 导出。页面导航继续由宿主确认；普通页面也可以用一个响应式页面链驱动它。

```ts
interface ColumnPage {
  key: string
  title: string
}

interface PageColumnsProps<P extends ColumnPage> {
  pages: readonly P[]          // 按根到当前页排列
  minColumnWidth?: number     // 有限正数，默认 280 CSS px
  motionEpoch?: number        // 默认 0；宿主在程序性重定位时随 pages 同批更新
}

type PageSlot<P> = {
  page: P
  selectedChild?: P           // 此栏在当前链上的直接子页
  current: boolean
  returningFrom?: P           // 键盘返回时，目标祖先下一级的入口
}
```

- **身份。** 设置页的 key 按配置范围及完整路径段编码，可用 `JSON.stringify([scope, ...path])`。标题、滚动位置和 URL 中的字段定位参数均独立于 key。宿主可在 P 上携带 schema 路径和导航目标，数组路径对应的编辑对象由第 6 节约束。
- **导航。** 插槽和面包屑通过宿主已有 `openPage`、`backPage` 请求变更。进入子页、改选兄弟用 push，点祖先及顶部返回用 replace，浏览器前进后退按访问记录恢复。请求失败或被拒绝，仍展示已确认的链。同页定位字段只改变焦点。加载完成前保留深链接，空链时由宿主呈现加载或错误。
- **重定位。** 相同的两条链既可能来自用户返回，也可能来自删除或外部校正。每次接受后者时一并改变 `motionEpoch`，即使目标 key 恰好相同也取消在途动画并直接呈现。加载补全、范围切换同理。这个值只控制当次呈现；业务事务号、URL 与导航历史仍由宿主管理。
- **栏目。** 用同一父节点下按 page.key 标识的一组页面同时承载多栏、单栏和过渡。页面角色只改变定位、叠放顺序及交互状态。只要 key 对应同一页面并仍需显示，变换栏位、进出层角色或栏数均复用该实例。各页始终读插槽传入的 page，可见祖先可以编辑或改选分支。

## 4. 宽度与导航控件

令 W 为稳定内容盒的实际内宽，M 为有效最小栏宽，G 为同时用于排版和测量的分隔线宽度，首版取 1 CSS px。对 W > 0，容量为 `max(1, floor((W + G) / (M + G)))`，取链尾最多这么多页。移动工作台强制一栏；桌面工作台和独立容器依自身宽度排版。无效 M 使用默认值。

| 场景 | 约定 |
| --- | --- |
| 首次显示或从后台恢复 | 用 ResizeObserver 观察容器。尚无有效尺寸时先显示当前页；已测量后遇到 W ≤ 0 或 KeepAlive 停用，保留最后有效容量、取消动画。重新激活后在首个有效测量直接排版 |
| 正好能再放一栏 | M=280 时，560/561px 分别显示一／两栏，841/842px 分别显示两／三栏。W 小于 M 时当前栏收缩，字段换行。每栏独立纵向滚动 |
| 宽屏浅路径 | 先为每栏分配 M。额外空间可等分至祖先栏达到约 340px（上限至少为 M），其余给当前栏。只有根页时栏占满内容区，分类列表本身靠左并限制阅读宽度，例如 36rem。宽度变化只重新排版 |
| 根地址 | 桌面和手机访问 `/settings` 都停在分类列表。此次设计取消桌面首分类的隐式预览；切换 view 后仍可按宿主已有 lastPaths 回到上次访问的位置 |
| 多栏与独立容器 | 多栏中每栏都有含边框 36px 的标题，父页入口行标记直接子页。桌面视图共用一条 36px 工具栏，复用 [WorkbenchBreadcrumbs](../../packages/vue-workbench/src/primitives/WorkbenchBreadcrumbs.vue) 显示全路径，折叠菜单保留隐藏祖先。分隔符只放在相邻项之间，同步修改折叠测量。独立单栏保留可达的祖先导航和当前标题 |
| 手机根页 | 固定外壳顶栏提供标题和全局导航。根页保留范围标签和搜索，省略仅有“设置”的面包屑和重复状态点。根页有草稿、冲突或可执行操作时才显示设置操作栏，问题和保存入口可达 |
| 手机深层 | 顶栏固定，统一返回按钮和当前页标题，全局导航图标行收起。正文省掉重复栏头，设置操作与可折叠祖先入口共用一行。用户可直达任意祖先；搜索和范围切换集中在根页，点根面包屑即可到达，原搜索词随 scope 保留 |

**转场归属。** 移动外壳统一处理一级区与详情区，顶栏固定。移动详情容器负责同区域的单栏层级变化。外壳提供移动单栏上下文；独立页面和桌面按容器宽度展开。区域返回时，详情页从 `useWorkbenchLeavingPath()` 取得原页面链。路由宿主在可选的 `presentation` 字段内传入详情描述，并继续管理导航、草稿和请求。
## 5. 单栏转场与输入命中

同一视图和范围内，只有实际单栏、已呈现且没有重定位的页面链变更参与转场。旧链为新链的严格前缀时前进，反之返回。跨多级返回直接在起点和目标间过渡。首次显示、同级换支、布局切换和减少动态效果直接呈现。

| 阶段 | 进入子页 | 返回祖先 |
| --- | --- | --- |
| 首帧 | 父页在底层原位，子页在上层右边界 | 已恢复位置的祖先在底层，子页在上层原位 |
| 约 220ms 内 | 子页从 +100% 到 0，父页从 0 到约 −18% | 子页从 0 到 +100%，祖先从约 −18% 到 0 |
| 完成 | 子页独自占满内容区 | 祖先独自占满内容区 |

两页使用不透明表面，在同一裁剪区内按各自描述绘制。保持离开页原滚动位置，目标页首帧恢复滚动。当按键返回跨越多级时，`returningFrom` 取旧链中紧接目标祖先的子页，供内容定位入口。菜单、弹窗和外壳顶栏在过渡区之外。

**命中和焦点。** 离开页的内部内容设 inert。包住它的视觉表面保持可命中，并拦住其覆盖区域的指针操作，不触发导航或冒泡到委托动作。返回中点击仍被子页盖住的区域应无动作；点击已经露出的父页可以继续下钻。键盘焦点移至可交互页的真实目标，通过 preventScroll 保留已恢复的位置。离开表面自身不参与 Tab 顺序。

**打断时序。** 例如从模型列表返回甲，在甲刚露出时点击连接参数。先使旧动画代次失效并取消位移，释放模型列表，保留甲的实例；用甲和连接参数开始下一次过渡。相反方向折返时也按 key 复用仍在场的页。每次更新先处理在途动画，再决定是否启动新动画，包括同级切换等无方向更新。捕获取消导致的 finished 拒绝；完成回调核对代次，恢复稳态后解除 fill/transform。隐藏、卸载、栏数变化或开启减少动态效果都清理在途效果。稳态单栏一页，转场最多两页。

## 6. llm-bot 设置接入

### 6.1 视图、栏目与真实焦点

设置 view 只注册 `mainArea`，根与后代全部映射到该区域。视图级组件拥有导航、配置范围、订阅、通知、工具栏及弹窗。每栏按自己的范围和 schema path 渲染；旧页卸载保存位置时，使用创建时绑定的 scope 状态。根栏复用现有分类、搜索和范围选择。schema、候选编辑和字段操作仍从已有资源编辑器及服务取得。

renderer 增加可选的直接子页选中信息，在对应入口按钮显示选中样式和可访问状态。栏头由容器统一提供。字段定位使用“绝对路径 + 目标用途”区分字段控件、类型选择器和子页入口，实际 focus 落在 input、select、textarea 或入口 button 上。以无判别字段的字符串／对象 union 为例，相同 path 下，编辑自由文本应聚焦文本控件，修改类型应聚焦类型选择器；返回则优先聚焦指定子页的入口按钮，入口已消失时回退到当前栏标题。每页用 useId 或等价实例前缀生成控件 id，使 label 始终关联本栏控件。

保存、取消、差异和问题提示各有一个入口。“发现模型”按当前路径所属的有效共享供应商决定，在其模型子页也可打开。QQ 状态呈现在当前实例 QQ 栏内，离开该栏时停止其轮询。根分类与其他祖先栏的布局独立。

### 6.2 集合操作与一次路径重定位

现状有两个独立风险。其一，`SchemaSettingsPage.moveEntry/removeEntry` 对数组发出整组 `edit(path, items)`，相同的新数组可能来自不同操作；llm-bot 的 `put` 在父路径 set 时还会删除后代缓冲，包括未确认的秘密输入。其二，`state.rename` 的响应或 SSE 可以先更新快照，路径校验 watcher 因而先于页面的 await 回调纠正旧地址。只在页面补一次 replace 无法覆盖这两种时序。

**建议契约。** 为资源编辑器的数组变更提供一个可选的结构操作处理入口，携带集合路径和追加、删除 index 或移动 from/to。移动定义为取出 from 项后插入最终下标 to。接入后每次动作只走该入口；独立旧消费者继续收到原有 edit 行为。追加成功后的进入新条目也由同一接入方安排。llm-bot 通过 SettingsService 现有命令队列、expectedRevision 和 commandId 提交操作，在服务端对实际条目执行；HTTP 回执和 SSE 使用同一份有序结构变更描述。这样在条目值相等或包含未下发的秘密时也能正确移动整个条目。已有 record rename 可沿用原有描述；通用 kit 只产生用户操作，不依赖业务协议。

| 确认的操作 | 对已有地址及所属状态的映射 |
| --- | --- |
| 重命名 record 祖先 | 对匹配旧前缀的地址替换前缀，保留有效后缀。清理已提交的重命名输入；被改名条目内其他未提交名称随页迁移 |
| 删除数组第 i 项 | 指向 i 的页面回到集合；更大下标减一，较小下标不变。删除 record 条目同样使该子树失效。清理已删除目标的名称和滚动位置 |
| 移动数组项 i→j | i 映射为 j；两个下标之间被越过的项按方向移一位；更深后缀原样跟随。交换相同内容的项也应用该操作 |
| 追加数组项或修改普通字段 | 追加保留已有下标；普通字段编辑保持当前对象和路由。只在一次用户追加动作成功后进入新项 |
| 更换 union 分支或无法识别的外部数组替换 | 验证当前路径在新分支的语义；失效时回到最近有效祖先。外部整组替换或刷新后无法证明数组条目身份时，退到受影响的集合页，隔离原条目未提交编辑 |

两个条目持久值完全相同、但有不同的未确认输入时，移动仍有界面语义。若服务按序列化结果判断草稿没有变化，也要让发起方从命令回执识别这次已接受的移动，按 commandId 迁移一次本地输入；其他客户端只有收到有序、可归属版本的结构事实时才跟随。不能从两个相同快照反推交换。接受外部更新但缺少结构事实的处理见上表。

**一次提交的顺序与职责。**

1. 宿主在设置状态接受结构变更的位置扩展已有 relocate 流程。用已确认的命令及版本将同一组映射恰好应用一次，HTTP/SSE 先后任意；旧回执、重试、取消或拒绝均不得再次迁移。对于本地立即投影的删除和分支切换，投影与原因同批发布，确认时按同一操作去重；失败时以实际草稿重算。
2. 以旧地址快照批量计算新地址，再统一替换索引，避免交换途中覆盖。处理编辑缓冲与选择中的待发送项（秘密输入是缓冲的派生值）、滚动、名称、字段定位和导航目标。已发命令的 payload 保持原样以便幂等重试。条目删除或身份不明时，把尚未确认的编辑按原对象保留为不可自动提交的冲突，不能借“使用本地值”把旧下标重新绑定到新占位项。
3. 状态层在发布新快照或投影的同一批次交付映射及变更来源。路由适配器对**当时仍活动的 scope 和路由**先映射，再用新数据验证，最终至多一次 replace。旧地址若已被另一条目占用，同批迁移或失效相应的组件身份，避免残留选区、局部输入或卸载回调覆写新状态。路由确认前不开放地址与内容尚未对齐的栏进行编辑。
4. 主动删除、改名、换分支引起的预期回退静默处理。坏深链或外部失效才提示一次；已知外部重命名且能完整跟随时继续编辑。状态层提供结构事实，Vue Router 和 toast 继续归视图适配器。移除 `SettingsPage.rename` 成功后另行导航的路径，旧 scope 或旧目标的迟到回执不得拉回用户。

### 6.3 深链接与 HTTP

settings 路由按路径段交给 Vue Router 编码。已用本地路由验证，含中文及 `anthropic/claude-3.7-sonnet` 的模型键可以往返，内部斜线保留为一个段。另用真实静态处理器和临时 Web 根目录发起 Fastify 注入请求，带 `Accept: text/html` 时，无点号模型页得到 200，`gpt-4.1` 和含编码斜线的版本模型页都得到 404。原因是 `src/http/static.ts` 对缺失文件使用 extname 判断 SPA 回退资格。

宿主修复应按路由命名空间识别设置页的 HTML 导航请求，允许末段含点号并回退到入口。已有文件仍优先，缺失的构建资源及 API 保持各自的 404，非 HTML 请求和文件根目录约束照旧。验收要覆盖服务器的首次 GET 和浏览器刷新，仅测客户端 push 无法发现这个问题。

## 8. 本轮复审重点

- **路径映射有没有漏掉写入者？** 重点看等待发送的编辑、已发命令重试、未确认秘密、已删除目标的冲突处理，及 SSE 先到时的去重。判断标准是任何后续提交都指向用户原先编辑的对象。
- **移动端是否始终只有一个转场负责人？** 以设置视图深链冷启动、内容延迟挂载及切换回旧 view 为例。检查外壳是否在内容挂载前就知道该不该移动，且手机始终单栏。
- **中间帧能否操作肉眼看到的页面？** 既检查被覆盖区域不会穿透，也要检查露出的父页能马上打开兄弟项；这比只验动画结束时截图更能发现问题。
